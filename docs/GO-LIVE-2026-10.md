## 7. Settings jo naye code ko chahiye

Jaanch 2 Oct 2026 (har `process.env` read ki jagah padhi). 27 me se koi bhi load par crash nahi
karta. Runtime settings `gcloud run services update … --update-env-vars / --update-secrets` se;
**`NEXT_PUBLIC_*` sirf build me jaati hai** — Cloud Run par set karne se kuch nahi hota, uske liye
`production/Dockerfile` me `ARG/ENV` aur `cloudbuild.yaml` me `--build-arg` chahiye.

**Deploy se pehle tay karo (BLOCKER):**

| Setting | Na ho to | Kya chahiye |
|---|---|---|
| `DMS_ENGINE_URL` + `DMS_ENGINE_READ_KEY` | Website se **free hosting trial har baar HTTP 500** ("We couldn't check whether you've had a trial before") | DMS engine ka URL + DMS ka `ENGINE_READ_API_KEY`. Ya faisla: trials abhi band |
| `DMS_ENGINE_COMMAND_KEY` (saath me) | Paid domain/hosting order `engine_not_connected` me rukta hai, khud provision nahi | DMS ka `BILLING_COMMAND_API_KEY` |

**Order ka jaal (galat order = sab users block):**
- `TURNSTILE_SECRET_KEY` — abhi **set mat karo**. Site key build me nahi jaati, to widget dikhta
  nahi, token nahi jaata, aur secret set hote hi signup + dono enquiry form **403** denge. Pehle
  `NEXT_PUBLIC_TURNSTILE_SITE_KEY` ko build arg banao → deploy → phir secret.
- `UNSUBSCRIBE_SIGNING_SECRET` — na ho to service-role key se kaam chalta hai (koi crash nahi).
  Pehla marketing campaign jaane **se pehle** tay karo; baad me badla to bheje gaye saare
  unsubscribe link toot jaate hain.

**Zaroori (feature chup-chaap band rehta hai):** `DOMAIN_REGISTRATION_LIVE`, `DOMAIN_RENEWAL_LIVE`,
`HOSTING_PROVISIONING_LIVE`, `HOSTING_RENEWAL_LIVE` (`1` = asli kharcha shuru — aapka faisla) ·

`NEXT_PUBLIC_DMS_PORTAL_URL` (login par "Hosting & domains" — build arg chahiye).
